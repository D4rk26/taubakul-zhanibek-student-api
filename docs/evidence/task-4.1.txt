## Notes: decisions
- Builds #1 above are SUCCESS with an empty pipeline: until this stage the Jenkinsfile in every branch
  was the empty placeholder from task 1.1. They prove that Jenkins checks out every branch.
- Setup wizard: disabled with the install state files in JENKINS_HOME (the same method the official
  Jenkins Docker image uses): jenkins.install.InstallUtil.lastExecVersion and
  jenkins.install.UpgradeWizard.state contain the WAR version 2.580.1, so Jenkins treats the initial
  setup as completed (InstallState RESTART, no wizard). The flag -Djenkins.install.runSetupWizard=false
  would need extra JVM options, but the brew service runs a fixed command and regenerates its plist.
- JCasC location: the brew service cannot pass CASC_JENKINS_CONFIG, so the plugin's default location
  $JENKINS_HOME/jenkins.yaml is used; it is a symlink to jenkins/casc.yaml in the repository.
- Admin password: casc.yaml contains only ${readFile:/Users/zhanibek/projects/jenkins-admin-password.txt};
  the file is outside the repository, chmod 600.
- GitHub credential: kept out of casc.yaml (casc.yaml is re-applied at every start; without the token it
  would reset the password to ""). It is applied once with jenkins/credentials.template.yaml:
  `gh auth token | (replace __GITHUB_TOKEN__) | jenkins-cli apply-configuration` — the token goes through
  pipes only, it is never written to a file, and Jenkins stores it encrypted in credentials.xml.
- API token for jenkins-cli/REST: generated via REST (generateNewToken), stored as "zhanibek:<token>" in
  ~/projects/jenkins-api-token.txt (chmod 600) and used as `-auth @file`.
