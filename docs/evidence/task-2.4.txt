## Why .env files, passwords and database credentials must not be committed
- Git history keeps everything forever: deleting the file in a later commit does not remove it
  from older commits; anyone with a clone can run `git log -p` and read it.
- This repository is public: every person on the internet can read every commit.
- Bots scan GitHub for leaked secrets within minutes of a push and use them automatically.
- Credentials differ per environment (laptop, Docker, server) and must be changeable without
  changing the code.
The correct way: the code reads environment variables (DB_USERNAME, DB_PASSWORD in application.yml,
no default password); real values live in a local .env file which is in .gitignore; the repository
contains only .env.example with placeholders; Jenkins gets secrets from Jenkins Credentials.
If a secret was leaked: rotate it immediately (change the password / revoke the token) — removing the
file or rewriting history afterwards is not enough, because the secret may already be copied.
