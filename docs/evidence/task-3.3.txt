## Notes
- `docker compose down` removes the containers and the network, but keeps named volumes. After `up -d`
  the new PostgreSQL container mounts the same volume taubakul-zhanibek-pgdata, so the student created
  before (zhanibek.persist@example.com) is still there, and the app log says "seeding skipped".
- `docker compose down -v` would also delete the volume taubakul-zhanibek-pgdata, i.e. all database
  data; the next start would create an empty database and seed the 3 demo students again.
- Exit code 143 after `docker compose stop app` = 128 + 15 (SIGTERM): Docker sent SIGTERM and the JVM
  shut down gracefully (exec-form ENTRYPOINT makes java PID 1, so it receives the signal).
- The image ID shown as BEFORE in step 6 (9057bb06…) differs from the ID in task 3.1 (f253edd3…)
  although Created is the same: `docker compose up --build` in task 3.2 rebuilt the image from the
  same cached layers; only the image manifest changed, not its content.
- `taubakul-zhanibek-linux` in the `docker ps -a` output above is an older, unrelated container
  (ubuntu:24.04, created 2026-10-11 for a previous lab, exited); it is not part of this Compose project
  and was not touched. Both project containers were removed by `down` and re-created by `up -d`.
