## Explanation: fast-forward vs --no-ff
main had no new commits since the feature branch was created (main is an ancestor of the branch),
so a plain `git merge` would do a fast-forward: Git just moves the main pointer forward to the last
feature commit. History stays linear and there is no trace that the work was done on a branch.
`git merge --no-ff` always creates a separate merge commit (967e8c2) with two parents. The graph
shows the branch and its 3 commits as one unit of work, and the whole feature can be reverted with
one `git revert -m 1 <merge-commit>`.
After the merge, `./gradlew clean build` on main passed again: 22 tests, 0 failures.
